6-1.何か・誰が使うか ✓〔仕様〕（H:20001280、2026-10-28 ごろ更新）

  • クラウド ブラウザは、ChatGPT Work に、クラウドの別のコンピューターの上の専用ブラウザを持たせる仕組み。ページを読み、ボタンを押し、フォームに入力し、公開のサイトとログインの要るサイトで手順を進める。頼みによって、つないだアプリ・プラグイン・クラウド ブラウザのどれか、または両方を使う
  • 提供: 対応地域の有料プランの ChatGPT Work。無料版と Go は除く（「excluding Free and Go」）。展開中は変わりうる。ワークスペースの権限にもよる
  • 利用者は、新しいサイトへのアクセスのたびに許可を求められる（既定）。設定で「毎回聞く」「自動で承認（危うそうなときだけ止まる）」「常に許可（勧めない）」を選べ、サイトごとに許可・拒否もできる。予約の確定や支払いなど取り消しにくい操作の前には、チャットで確認を求める
  • サイトの側で止めることもある: 「自動のブラウザ エージェントからのアクセスを制限するセキュリティの仕組みを使うサイトがある。…この制限はサイトが決めるもので ChatGPT ではない。…クラウド ブラウザの流入を許すかは、最後はそれぞれのサイトが決める」✓（H:20001280）
  • クラウド ブラウザは端末のブラウザと別で、自分の Cookie・ログインを持つ。利用者の手元のブラウザのタブ・履歴・保存したパスワード・Cookie は使わない ✓（H:20001280）

6-2.許可の仕方（開発者文書の「Help ensure cloud browser access to your site」）✓〔仕様〕（D:Commerce、2026-11-24 取得）

  • サイトのファイアウォールが、利用者が頼んだ訪問を止めたり途中で切ったりすると、購入などの目的を果たせない。ChatGPT の agent profile をファイアウォールの許可リストに入れる。他のセキュリティの制御はそのままでよい
  • Akamai・Cloudflare・HUMAN・Vercel は、ChatGPT の要求の署名を自動で確かめる。設定の手順は §5-3 の表の右の列
  • FAQ:
    • 決済など特定の操作の前に人の確認を必須にできるか → サイトの持ち主が操作を制御する機能はまだ無い。ただし全利用者について、重大な操作の前に人の確認を求めている
    • 特定のページや商品だけエージェントに見せないことはできるか → 例外はサイト全体に効く。既存のページ単位のアクセス制御はそのまま残す
    • 他の bot に影響するか → しない。確認済みのクラウド ブラウザの訪問を許す規則は、他の流入の扱いを変えない。この訪問は利用者の代わりのもので、OAI-SearchBot を含む OpenAI のウェブ クローラーとは別
    • 商品フィードとの関係 → 独立しているが補い合う。フィードは商品の発見に、クラウド ブラウザは加盟店のサイトでの次の操作に。フィードを設定していなくても、確認済みの利用者はクラウド ブラウザでサイトを使える
    • プラグインとの関係 → 独立しているが補い合う。プラグイン（MCP）があると速く使えることがあり、作って公開することを勧める
    • 支払いや注文の誤りは誰が扱うか → 操作の責任は最後は顧客にある。顧客が自分で操作したときと同じように対応する

6-3.署名の確かめ方（Web Bot Auth）✓〔仕様〕（D:Commerce）

  • ChatGPT は Web Bot Auth で一部の自動のブラウザの要求を名乗る。これは署名つきのクラウド ブラウザの要求の話で、ウェブ クローラーの話ではない。仕組みは HTTP Message Signatures（RFC 9421）
  • 署名つきの要求には Signature、Signature-Input、Signature-Agent（値は "https://chatgpt.com"）の 3 つのヘッダーが付く
  • 公開鍵: https://chatgpt.com/.well-known/http-message-signatures-directory
  • 自分で確かめる手順: ①Signature-Agent が引用符も含めて "https://chatgpt.com" と完全に一致するか ②公開鍵を取る ③RFC 9421 に沿って Signature と Signature-Input を検証 ④許可の例外は署名を検証してからかける

6-4.運用の判断への効き方

  • クラウド ブラウザの許可は ChatGPT の広告の審査の点検項目ではない〔推測。H:20001243 は OAI-AdsBot と OAI-SearchBot しか挙げず、D:Commerce はクラウド ブラウザをクローラーと別と書く〕。広告を出すために必要なのは OAI-AdsBot
  • 逆に、広告が出る利用者（無料版・Go）は、クラウド ブラウザを使えない（H:20001280）。広告から LP に来る人は、ふつうは自分のブラウザか ChatGPT の中のブラウザで開く〔推測。広告のクリックでどのブラウザが開くかは記載なし ?〕
  • それでも EC・予約のサイトは、有料プランの利用者が ChatGPT に「このサイトで予約して」と頼む場面のために、クラウド ブラウザを止めていないかを点検する価値がある（00§9-2「広告以外の手」）。これは広告の運用とは別の判断として、サイトの担当と決める〔推測〕
  • 00§9-2 は「クラウド ブラウザを弾かない」を加盟店の手に挙げ、国の制限は記載なし〔推測: 使える〕と書く。今回の本文で、使える利用者の側は「対応地域の有料プラン」と分かった（地域の一覧は記載なし ?）

9-1.公式の文 ✓〔仕様〕（H:20001207 英語版、2026-11-15 ごろ更新）

  • 2026-11-22 ごろに更新された「Why conversion totals differ between platforms」（H:20001632）は、媒体ごとに数字が合わない理由として、数えるものの違い・帰属の違い・日付・反映の遅れ（24〜48 時間）・同意やブラウザの制限・推計を挙げる。クローラーの訪問は挙げていない（2026-11-24 時点）

  • GA4 の「ChatGPT の広告からの流入」と Ads Manager のクリック数を比べるとき、GA4 が多すぎる日があればクローラーの訪問を先に疑う。逆に GA4 が少ないのは、同意・ブラウザの制限・oppref や UTM の欠け（06§7-2）を疑う〔推測〕

13.よくある思い込みと実際

思い込みブラウザで LP が開けるから審査は大丈夫

実際ブラウザで開けても、クローラーが同じ中身を受け取るとは限らない。HTTP の成功の応答だけでは中身が読み込まれたことにならない

根拠: ✓ H:20001243

思い込みトップページが開くから広告のリンクも動く

実際トップの成功は広告のリンクが動く証拠にならない。パラメータ込みの完全な URL で、端末・地域ごとの行き先まで確かめる

根拠: ✓ H:20001243

思い込みrobots.txt で OAI-AdsBot を許したから通る

実際robots.txt だけでは足りない。WAF・CDN・bot 対策・JavaScript の確認画面・CAPTCHA・認証・地域の規則が別に止める

根拠: ✓ H:20001243

思い込み「AI に学習させたくない」から OpenAI の bot は全部止める

実際学習の bot は GPTBot。OAI-AdsBot は広告として出されたページだけ訪れ、学習に使わない。止めると広告の審査が通らない。設定は互いに独立

根拠: ✓ D:Bots

思い込みGoogle の AdsBot を通しているから OAI-AdsBot も通る

実際名前も仕組みも別。Google の AdsBot は robots.txt の * を無視するが、OAI-AdsBot の扱いは記載なし

根拠: ✓ D:Bots、G43§6-2／?

思い込みCloudflare なら何もしなくてよい

実際Cloudflare は OAI-AdsBot を確認済みの bot として許可している。ただしサイト側の独自の規則・AI の bot の遮断は別〔推測〕。点検は省かない

根拠: ✓ H:20001243＋〔推測〕

思い込みクラウド ブラウザを許可すれば広告の審査も通る

実際クラウド ブラウザは利用者の代わりにサイトを操作するもので、クローラーとは別。広告に要るのは OAI-AdsBot。しかもクラウド ブラウザは有料プランだけで、広告が出る無料版・Go の利用者は使えない

根拠: ✓ D:Commerce、H:20001280

思い込みサポートに頼めば LP の確認を手で通してもらえる

実際手動の回避に頼らない。LP を読めるようにして出し直す

根拠: ✓ H:20001243

思い込み直したのだから承認される

実際直しても承認は保証されない。審査は続く

根拠: ✓ H:20001243

思い込みGA4 の ChatGPT 広告の流入がクリック数より多いのは、計測の誤り

実際審査のクローラーがパラメータ付きで LP を訪れ、解析ツールで有料の流入に見えることがある（課金はされない）

根拠: ✓ H:20001207

思い込みLINE の友だち追加やオープンチャットに直接飛ばせば早い

実際広告からメッセージングのチャット・グループへ直接リンクできない（v1.7）。自社サイトの中で連絡手段として置くのは可

根拠: ✓ P§3

思い込み商品画像は LP と同じ許可で済む

実際商品画像の URL には OAI-SearchBot が要る。画像のホストが別なら、そちらの設定も見る。403 でフィードの処理が止まりうる

根拠: ✓ H:20001243
