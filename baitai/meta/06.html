2.道具の全体と器（データセット）

この節の要点
  • 新しく作るなら、ウェブもオフラインも「1 つのデータセット＋CAPI」に寄せる
  • 代理店に渡す権限は、広告アカウントだけでなくデータセットにも要る
  • データセットが計測の単位
  • 広告セットで選んだイベントだけが最適化の対象

2-1.何がどこにあるか ✓公式本文（B-24、B-10、B-22）

道具役目置き場所
データセット（旧 ピクセルの器）ウェブ・アプリ・実店舗などのイベントを 1 か所でつなぎ、管理する。ヘルプは「データセットとピクセル: Meta ピクセル、コンバージョン API やその他のツールを使用して、ウェブサイト、アプリ、実店舗など、さまざまなソースからのイベントデータをリンクして管理」と書くビジネスポートフォリオのデータソース

コンバージョン API（CAPI）サーバー・CRM・店舗などから直接イベントを送る。ウェブ・実店舗・メール・ビジネスチャット・電話・アプリ・オフラインに対応同じデータセットに入る

  • ✓ CAPI はアプリイベント API やオフラインコンバージョン API の代わりに使える。すでに旧 API を使っていれば続けられるが、「データセットの作成が必要な場合には使用できません」とヘルプは書く（B-10）。開発者文書は旧オフラインコンバージョン API を「レガシー」と呼ぶ（B-28）
  • ✓ オフラインのイベントは CAPI で送る場合、データセットに結び付ける必要がある（B-28）

2-2.運用の判断への効き方

新しく作るなら、ウェブもオフラインも「1 つのデータセット＋CAPI」に寄せる。

旧オフラインイベントセットや旧 API で新しく組まない〔推測〕（B-10・B-28 の「レガシー」「代わりに CAPI」から）

代理店に渡す権限は、広告アカウントだけでなくデータセットにも要る。

データセットには広告アカウント・メンバー・パートナーを別々に足す（ヘルプの関連ページ名で確認。本文は未読 ?）

カスタムコンバージョンは広告アカウント単位で見え方が変わる。ポートフォリオにアクセスできる人は両方から、広告アカウントだけの人はそのアカウントで作ったものだけ見える ✓ 本文（B-20）

2-3.Google との違い

Google はコンバージョン アクションが「計測の単位」で、タグはそれを動かす部品。Meta はデータセットが計測の単位で、その上に標準イベント・カスタムイベント・カスタムコンバージョンが乗る。Google の「メイン／サブ」に当たる区分は Meta に無く、広告セットで選んだイベントだけが最適化の対象になる（S-13）。

3.Meta ピクセル

この節の要点
  • 旧名 Meta Pixel Helper
  • 2026-08-03 から
  • ピクセルだけの構成は、今は「最低限」
  • 購入には必ず value と currency を付ける
  • 自動検出の標準イベント（2026-08-03 以降の既定）は、意図しないイベントを作りうる
  • オーディエンス（リターゲティング）の材料と、計測と、最適化の信号を 1 本で兼ねる

3-1.仕組みと置き方 ✓公式本文（B-22、B-19）

  • ベースコードを全ページの <head> に、イベントコード（fbq('track','Purchase',{value:…,currency:…}) など）をページごとに置く
  • ピクセルの使い道としてヘルプが挙げるのは、①狙いどおりの人に出ているかの確認と見込み客の発見・リターゲティング、②自動入札で成果を出しやすい人に届ける、③効果の測定

3-2.標準イベント（17 種）✓公式本文（B-19）

支払い情報の追加（AddPaymentInfo）、カートに追加（AddToCart）、ウィッシュリストへの追加（AddToWishlist）、登録完了（CompleteRegistration）、問い合わせ（Contact）、製品のカスタマイズ（CustomizeProduct）、寄付（Donate）、場所の検索（FindLocation）、チェックアウト開始（InitiateCheckout）、リード（Lead）、購入（Purchase。value と currency）、スケジュール（Schedule）、検索（Search）、トライアル開始（StartTrial。predicted_ltv あり）、応募（SubmitApplication）、サブスクリプション登録（Subscribe。predicted_ltv あり）、コンテンツビュー（ViewContent）。

  • ヘルプはコンテンツビューについて「URL に訪問があったことはわかりますが、訪問者がウェブページで何を実行または閲覧したかはわかりません」と書く（B-19）
  • ✓ 標準イベント以外の名前で送るのが「カスタムイベント」。最適化に使うにはカスタムコンバージョンを経て標準イベントのカテゴリを選ぶのが勧められる（§7）

3-3.Cookie の設定 ✓公式本文（B-23）

  • 既定は「ファーストパーティ Cookie とサードパーティ Cookie の両方を使う」。ファーストパーティ Cookie は使えるブラウザが多く、保存期間も長い
  • ファーストパーティ Cookie をオフにすると「測定とレポートの正確性も低下」とヘルプは書く
  • ? ファーストパーティ Cookie（_fbp・_fbc）の有効期間はヘルプ本文に書かれていない

3-4.詳細マッチング（ピクセル側の照合の強化）✓公式本文（B-25）

方式中身

  • 効き目としてヘルプが挙げるのは、アトリビューションされるコンバージョンの増加、カスタムオーディエンスの拡大、コンバージョン単価の削減

3-5.点検の道具: Meta Ads Data Advisor（旧 Meta Pixel Helper）✓公式本文（B-35）

  • Chrome・Edge の拡張機能。旧名 Meta Pixel Helper。既存の利用者は自動で更新され、診断の機能はそのまま
  • ピクセル・CAPI（GTM 経由を含む）の設定、Shopify・WooCommerce の接続、Salesforce・HubSpot の CRM データ、カタログ、詳細マッチングの設定まで手伝う。設定の自動化にはログインと広告アカウントの管理者権限が要る（検出と点検はログインなしで動く）
  • 2026-08-03 から、Data Advisor で新しくピクセルを作ると、標準イベントの自動検出が既定でオン（外せる）
  • 日本語ヘルプの重複除外のページは「Chrome 拡張機能の Meta 広告データヘルプツール」と書く（B-13）

ピクセルだけの構成は、今は「最低限」。

ブラウザの読み込み失敗・接続・広告ブロッカーで落ちる分を CAPI で補うのが Meta の推奨（B-10、B-17）。まずピクセル＋詳細マッチング（自動）を入れ、次に CAPI

購入には必ず value と currency を付ける。

値の最適化（ROAS 目標・価値の最大化）とレポートの ROAS の前提（B-19、B-21）

5-2.重複除外の条件 ✓公式本文（B-13）
