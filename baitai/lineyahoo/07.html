0.先に結論（10 行）

  1. 01

    LP の「内容」と「ドメイン」に、公式のはっきりした決まりがある。 最終リンク先 URL・スマートフォン向け URL・クリック後に表示されるページは同一の内容、表示 URL を含む 4 つの URL のドメインは一致（検索 H000044815、ディスプレイ H000044231）✓〔仕様〕

  2. 02

    計測のためのリダイレクトは「トラッキング URL」に置き、最終リンク先 URL には着地のページを入れる。 ディスプレイのヘルプは、計測用の URL から別のドメインの LP へ飛ぶ例（パターン 3・4）を、この形で示す ✓〔仕様〕（H000044231）

  3. 03

    トラッキング URL は審査される。 ディスプレイの運用型では、上位の階層（アカウント・キャンペーン・広告グループ）のトラッキング URL に不備があると、配下の広告がまとめて否認されうる ✓（H000044231）。検索の上位階層の URL オプションは再審査の依頼ができない（直して設定し直す）✓（H000044782）

  4. 04

    {lpurl} は、アカウント・キャンペーン・広告グループのトラッキング URL では必須。 検索の動的検索連動型広告の広告にも必須。キーワード・クイックリンクと、検索のそのほかの広告では任意 ✓（H000044782、H000044231）

  5. 05

    同じ名前のパラメーターでも、検索とディスプレイで返す値が違う。 {device} は検索が m／t／c、ディスプレイは DESKTOP／SMARTPHONE／TABLET／CTV（NONE）。{campaignid} は検索が「トラッキング用の ID（キャンペーン ID とは異なる）」、ディスプレイは「キャンペーン ID」✓（H000045007、H000044463）

  6. 06

    広告のトラッキング URL は、キーワードの最終リンク先 URL より優先される。 キーワード単位で LP を変えたいなら、キーワードにもトラッキング URL を置くか、広告のトラッキング URL を外す ✓（H000044782 の表）

3-3.主体者とアカウント名、別ドメインのサイト ✓〔仕様〕（H000044448、2026-11-24 本文）

  • 広告の主体者情報（会社名・氏名）は「アカウント名」と一致する必要がある
  • 今のサイトと同じ主体者の別ドメインのサイトなら、同じアカウントで出せる。キャンペーンの設定（配信設定・1 日の予算など）を同じにするなら、ドメインごとに広告グループを作ることを公式は勧める。同じ広告グループに別ドメインのサイトを入れることもできるが、サイトとキーワード・クリエイティブ・最終リンク先 URL の関連性が低いと掲載できない
  • キャンペーンの設定を変えるなら、新しいキャンペーンと広告グループを作って登録する
  • 主体者が違うサイトは、同じアカウントでは出せない。新しいアカウントを足す（問い合わせが要る）

運用の判断への効き方

  • LP を PDF にしない。資料請求の着地を PDF のダウンロードにしたいときも、PDF へのリンクを置いた HTML のページを LP にする（H000044188 の (1)）
  • ポップアップ型の離脱防止・アプリ起動の自動化は入れない。「戻れない」「意思の確認なく起動」はアカウントの開設の段階で断られる決まり（H000044188 の (2)・(5)）。開設後の広告の否認は 34§2-13
  • ブランドごとに会社が違うグループ企業は、LP の運営会社に合わせてアカウントを分ける。代理店がまとめて運用していても、主体者がアカウント名と一致しない LP は同じアカウントに入れられない（H000044448）
  • 同じ会社の複数サイトは、ドメインごとに広告グループを分ける（公式の推奨）。品質インデックスの「広告の関連性」「LP の利便性」もキーワード × 広告文 × LP で見られるので、混ぜると原因を切り分けにくい〔推測〕

  • 検索の {campaignid} を管理画面のキャンペーン ID と突き合わせても一致しない。キャンペーンの識別は、カスタムパラメーター（{_cp}=名前）を自分で置くほうが確実〔推測〕
  • キーワードごとに LP を変える設計なら、広告にトラッキング URL を置かないか、キーワードにもトラッキング URL を置く（§6-6 の表）。置き忘れると、キーワードの最終リンク先 URL が無視されて広告の URL に流れる
  • 計測のサーバーへリダイレクトするなら {lpurl} を先頭以外に置き、計測側が 1 回デコードして転送する前提で組む。2 段以上のリダイレクトなら {lpurl+2}（ディスプレイの本文は「複数回リダイレクトする場合に有用」と書く）
  • UTM などの固定の値は、上位の階層のトラッキング URL（{lpurl}?utm_source=yahoo&...）に 1 つ置けば配下にすべて効く。ただし上位の誤りは配下全体に広がる（§5-1）。変える前に URL のテスト機能（ディスプレイ）
  • 取ったデータを広告主以外へ渡す使い方（再販・データ提供）はしない（§6-7）

14.判断の型

状況まず確かめる次の手
「リンク先」系の否認が出た§11 の 1〜6、34§2-13 の否認理由直して再審査（34§5）。上位の URL オプションなら設定し直し（§5-1）

キーワード別の LP に人が来ない広告にトラッキング URL があるかキーワードにトラッキング URL を足すか、広告の分を外す（§6-6）
