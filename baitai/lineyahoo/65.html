1-2.公式 MCP サーバー（④）のくわしい中身 ✓公式P-19（README.ja.md と src、v0.0.1、2026-09-11 作成）

MCP クライアントの設定は "type": "http" と URL だけ

  • 鍵の渡し方: 環境変数 LY_ADS_CLIENT_ID・LY_ADS_CLIENT_SECRET（MCP 用 OAuth クライアント）、LY_ADS_MCP_JWT_SIGNING_KEY（自分で作る 32 文字以上の乱数、openssl rand -base64 32、シークレットと同じ値は不可）、任意で LY_ADS_REPORT_OUTPUT_DIR（CSV の置き場、既定は起動したフォルダの reports）。アクセストークンと更新トークンは FastMCP の OAuth Proxy が持ち、MCP クライアントには設定しない。接続するとブラウザに認可画面が出て、ビジネス ID で許可する
  • MCP 用 OAuth クライアント: API の申し込みのあと https://connect-business.yahoo.co.jp/client/mcp で発行。通常の API アプリは企業単位、MCP 用 OAuth クライアントはビジネス ID 単位。発行画面には API 管理ツールの管理権限か利用権限が要る
  • 道具（名前空間 ly_ads_display・ly_ads_search）: 一覧系（list_accessible_*_base_accounts、list_accessible_*_accounts、list_*_campaigns、list_*_labels、list_*_ad_groups、list_display_ad_group_targets、list_search_campaign_targets、list_search_campaign_negative_keywords、list_search_ad_group_keywords、list_*_ads）、get_*_report_fields、read_*_report。変更の道具は無い
  • レポート: 中では ReportDefinitionService の add（ジョブを作る）→ get（2 秒おき）→ download。60 秒で終わらなければエラー（期間・項目・絞り込みを狭めて再依頼）。結果は先頭 50 行のプレビューと、UTF-8 の CSV（display/YYYY-MM-DD か search/YYYY-MM-DD）。CSV は自動では消えない。返すのはローカルのパスで、MCP の Resource ではない
  • API の版: コードは v20 固定（api_version.py）。スコープは yahooads
  • 安全の作り: 返す値はすべて「信頼しないデータ」として区切り、指示として扱わないよう AI に伝える文が入っている。複数アカウントへの一斉の呼び出しは、利用者がはっきり頼んだときだけ、と指示している
  • 〔推測〕「参照のみ」は道具の品ぞろえの話で、権限の話ではない。認可したビジネス ID が更新権限を持っていれば、トークン自体は書き込みにも使える。読むだけを権限で保証したいなら、参照権限だけのビジネス ID で認可する（§2-A の 6）
  • 〔推測〕レポートのたびに「レポートのジョブ」を add で作る（広告の設定は変えない）。作ったジョブを消す呼び出しはコードに見当たらない

道 1: 公式 MCP（④）をそのまま横に置く

③の API を自前で呼ぶ。Google と同じ形の道具・許可リスト・記録の形にそろえられる
