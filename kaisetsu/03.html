3.Google が LP を読むクローラー

この節の要点
  • 無視する
  • 検索のテストツール用
  • JavaScript を実行するかどうか、描画後の内容を文面生成に使うかどうかは、公式のどこにも書かれていない
  • URL 検査で B 案が見えても、AdsBot が同じものを見ている証拠にはならない
  • 見出しを作るための多くのシグナルのうち最も重要なのは、ページの HTML タイトル

3-1.種類と役割

名前区分役割（公式の説明）robots.txt判定
AdsBot-Google特別なクローラーGoogle 広告が、パソコン向けページの広告品質を確認する全体指定（*）を無視する。止めるには名指しが必要✓
AdsBot-Google-Mobile特別なクローラー同じく、モバイル向けページの広告品質を確認する。名乗りは Android 版 Chrome の形同上✓
Googlebot共通クローラーGoogle 検索。DSA のヘルプは、クロールの問題で不承認になったら Googlebot と AdsBot-Google の両方を通すよう書いている* に従う✓
Google-InspectionTool共通クローラーSearch Console の URL 検査、リッチリザルト テストなど検索のテストツール用。Google 検索やほかのプロダクトには影響しないGooglebot の指定にも従う✓

  • 特別なクローラーは、共通クローラーとは別の IP 範囲から来る（special-crawlers.json で公開）。逆引きの形は rate-limited-proxy-***.google.com ✓
  • AdsBot はアメリカから来ることが多い（広告ポリシー 16428223）✓。クローラー全般の説明では、Google のクローラーは主にアメリカの IP から来て、アメリカからの接続が遮断されていると分かれば、ほかの国の IP から試すことがある（overview-google-crawlers）✓。この説明は特別なクローラーを名指ししていない。AdsBot が日本の IP から来る場面があるかは ?
  • リンク先の要件（ポリシー 6368661）は英語版と日本語版で項目の中身が違う。どちらにも「クロールできないリンク先／Destination not crawlable」の項目がある。そのうえで日本語版は「アクセスできないリンク先」にも「Google AdsBot がランディング ページをクロールできない」（AdsBot に 404・403 を返す、robots.txt で止める、サーバー側で拒否する）を含める。英語版の Destination not accessible は「対象地域でアクセスできない」だけで、AdsBot には触れない ✓（2026-11-17 に両方を取得して確認）
  • 名乗り（ユーザー エージェント）は偽装できるので、本物かどうかは IP で確かめる ✓

Google 検索（Googlebot）常に新しい Chromium で JavaScript を実行し、描画後の HTML をインデックスに使う。描画は待ち行列に入るので、取得より遅れることがある✓
AdsBot（Google 広告）JavaScript を実行するかどうか、描画後の内容を文面生成に使うかどうかは、公式のどこにも書かれていない?
文面生成がどのクローラーの取得結果を使うか記載なし。DSA は「Google のウェブ クロール技術」、P-MAX のページフィードは「インデックス登録の確認に役立つ」と書くだけ?
  • 手がかり（結論ではない）: AdsBot-Google-Mobile は Chrome の形で名乗り、クローラー一覧は「Chrome の版数は Googlebot が使う Chromium に合わせて上がる」と注記する。広告ポリシーのヘルプ（16431325）は、AdsBot の名乗りでページを開いて「ふだんのブラウザと同じように読み込まれること」を確かめるよう勧める。どちらも「描画後の文面を文面生成に使う」とは言っていない
  • 注意: Google 広告のヘルプ（9229701）と広告ポリシーのヘルプ（16428223。Chrome のデベロッパー ツールの Network タブと並べて挙げる）は確認手段に Search Console の URL 検査を挙げるが、URL 検査が使うのは Google-InspectionTool で、公式の説明では検索のテスト用。URL 検査で B 案が見えても、AdsBot が同じものを見ている証拠にはならない（このメモの推測）
  • 第三者: Prerender（描画サービスの販売会社、2026-08-07 更新の記事）は「AdsBot はブラウザのようには JavaScript を描画しない」と主張するが、Google の資料も自社の検証も示していない。逆に「描画できる」と書く業者ページもあり、どちらも裏づけがない
  • AdsBot について公式に書かれていること・いないことの一覧は 94_裏取りの記録_41-44.md の 2-2 にある（AdsBot が JavaScript を実行するかは、そこでも ? のまま）

3-4.DSA・P-MAX のページ内容の取得

  • DSA ✓（2471185）: 見出しはサイトの内容から作る。見出しを作るための多くのシグナルのうち最も重要なのは、ページの HTML タイトル。サイトのタイトルやよく使われる語句で LP を選ぶ。HTML タイトルと内容がきちんと書かれたサイトで最もよく働く。大半が画像のサイトや、ログインが必要なサイトは苦手
  • DSA のクロール不可 ✓（9229701）: URL を名指しした対象やページフィードは「クロールできません」で不承認になる。それ以外の指定方法では、クロールできなくてもエラーが出ない（気づけない）。リダイレクトは 10 回未満
  • P-MAX ✓（14337539）: 設定の変更が行き渡るまで 24〜48 時間かかることがある。複数ドメインや事業が多いサイトでは、見出し・説明文と着地先が食い違うことがある

4.ブラウザ側で文面を差し替える A/B テストを、広告システムは読むか

観点分かっていること判定
Google 広告の文面生成が、ブラウザ側で差し替えた文面を読むか公式の記述は見つからなかった。検証した第三者の記事も見つからなかった（英語・日本語とも）?
広告ポリシー上、A/B テストは問題かクローキングは「ポリシー違反を隠すために、人や Google に違う内容を見せること」。人によって少し違う内容を見せるのは構わないが、宣伝する商品・サービスは全員に同じである必要がある（adspolicy/answer/15938075）✓

参考: Google 検索（SEO）側の A/B テストの扱い ✓（Search Central「A/B テスト時に Google 検索への影響を最小限に抑える」、最終更新 2025-12-10）

項目内容
ブラウザ側の出し分けURL を変えず、JavaScript でどの案を見せるか決める方法は認められている
クローキングGooglebot にだけ別の URL 群を見せてはいけない。サーバー側の判定でも robots.txt でも同じ
CookieGooglebot は基本的に Cookie を使わない。Cookie で制御するテストでは「Cookie を受け付けないブラウザに見える版」だけを見る
rel=canonicalURL を分けるテストでは、別案の URL から元の URL へ向ける。noindex より canonical
302振り分けのリダイレクトは 302（一時）。301 は使わない。JavaScript でのリダイレクトも可
期間必要な期間だけ。終わったらテスト用の仕組みをすぐ外す。長すぎると検索エンジンを欺く行為とみなされうる
小さな変更ボタンの文言など小さな変更は、クロールされても検索結果への影響はほとんどない

このメモの推測（公式の裏づけなし）。読む側が B 案を見るには 3 つの関門がある。

  1. LP を取得するクローラーが JavaScript を実行する（3-2 のとおり不明）
  2. 50:50 の振り分けで B に当たる（Cookie を持たないクローラーは、来るたびに振り分け直される可能性がある）

3 つとも通ったときだけ B 案が材料になりうる。どれか 1 つで止まれば、材料は配信された HTML に書かれた A 案と、共通の title・meta description になる。

15.この問いを確かめられるテストの組み方

問い: LP テストで出し分けた B 案の文面が、AI Max の作る見出し・説明文の材料になるか。

15-1.出典で言えること（組み方の土台）

土台にする事実出どころ
生成に使う URL は広告単位の最終ページ URL16739013
タイトル・説明・メタタグは抜き出しの対象と明記されている11259373
生成文面は、元にしたソースが変わると自動で消える。LP の変更は 48 時間以内に反映16740321、11259373
AdsBot のクロールは約 2 週間ごとwebmasters 9679690
プレビューは、オプトインなしで URL から最大 10 個の例を作る11259373
生成された文面は source = AUTOMATICALLY_CREATED、画面では［提供者:］＝［Google AI］で見分けられるAPI、16739013
実際に出た見出しは［検索語句と広告の組み合わせ］で見られる16470459

A/B で少し違う内容を見せることは、広告ポリシー上は問題ない。検索側の指針では、テストは必要な期間だけadspolicy 15938075、Search Central

15-2.いまの観察から言えること・言えないこと

  • 言える: 生成 2 本が title と同文なのは、公式の作り方どおり
  • 言えない: title は A・B 共通なので、「B を読んだ」「読んでいない」のどちらの証拠にもならない。本文は A 案すら使われた形跡がまだ無い。つまり今は「本文が材料になる段階」に達しているかどうかも分からない

15-3.テストの組み方（ここからはこのメモの推測。公式の裏づけはない）

考え方: 「どこに書いた言葉が広告文に出てくるか」を、目印の言い回しで追う。目印は、title・meta description・キーワード・既存の広告・もう一方の案のどこにも無い、事実に基づく短い言い回しにする（うその特典や数字は使わない。生成文面は広告主の責任になるため）。

テストやること費用・期間読み方
0. ツールが AdsBot を対象にするかChrome の開発者ツールで、名乗りを AdsBot-Google と AdsBot-Google-Mobile に変え、Cookie を消して LP を数回開く。B 案への差し替えが起きるかを見る0 円・10 分差し替えが 1 回も起きなければ、ツールがロボットを対象外にしている可能性が高い。その場合、B 案は材料にならないとほぼ言える（テスト 1〜3 は不要）
1. プレビューで 3 つの URL を比べる(a) 今の LP（タグあり） (b) B 案を HTML に直接書いた静的な複製ページ (c) A 案だけの静的な複製ページ、をプレビューに入れ、日を変えて各 5 回ほど例を作る。複製ページは公開するがリンクは張らず、canonical を本体へ向ける0 円・2〜3 日(b) で B の言い回しが出て (a) で 1 回も出ない → 差し替え後は読まれていない可能性が高い。(a) でも出る → 読まれている。(b) でも出ない → 本文がそもそも使われていない（この規模では title 中心）
2. 本番で目印を追う目印を 3 か所に置く。M1＝meta description（A・B 共通、静的）、M2＝配信される HTML の A 案の本文、M3＝差し替えで入る B 案の本文だけ。テスト期間中は出し分けを B 100% にして、振り分けの揺れを消す。毎週、source = AUTOMATICALLY_CREATED の文面一覧と［検索語句と広告の組み合わせ］の見出しを記録する追加費用なし・最低 4 週間（クロール 2 巡ぶん）下の判定表
3. AdsBot が差し替え後の合図を送るか差し替えが終わった直後に、自分のサイト内の計測用アドレスへ「どの案を描画したか」を 1 回送る小さな処理を足す。記録から、AdsBot の IP 範囲（公式の一覧で照合）からのアクセスを拾う。外部のサービスへは送らない開発 1〜2 時間・4 週間AdsBot から合図が届く → JavaScript を実行し、その案を描画している。届かない → 実行していない可能性が高い（ただし、描画はしても合図の送信だけ省くクローラーもありうるので、否定の証拠としては弱い）

テスト 2 の判定表

生成文面に現れた目印読み取れること
M3 が現れた差し替え後の内容が材料になっている。B 案は材料になる
M1 と M2 が現れ、M3 は現れない本文は読まれるが、配信された HTML のまま。B 案は材料にならない
M1 だけ現れた抜き出しは title・meta 止まり。本文は（A も B も）この規模では使われていない。B を読むかどうかは判定できない
どれも現れない生成自体が進んでいない。配信量か LP の内容量が足りず、結論は出せない

15-4.進め方と注意

  1. 1

    テスト 0 → テスト 1 の順に進める。ここまで 0 円で、多くの場合は方向が見える

  2. 2

    テスト 2・3 は、0 と 1 で決着しなかったときだけ。M1（meta description）は「仕組みが動いているか」を確かめる基準として必ず入れる。これが無いと、何も出なかったときに「読まれていない」のか「生成されていない」のか区別できない

  3. 3

    週 160 回ほどの表示では、生成文面が配信されるのを待っても判定できない。見るのは表示回数ではなく「一覧に現れたか」。表示 0 回の生成文面が一覧に出るかは未確認（13 章）なので、管理画面と API の両方を見る

  4. 4

    B 100% の期間は LP テストの計測が止まる。検索側の指針（テストは必要な期間だけ）にも沿うよう、4 週間で切り上げる

  5. 5

    期間中は、広告・キーワード・最終ページ URL を変えない。生成文面は文脈が変わると消える（16740321）ため、変えると結果が読めなくなる

  6. 6

    プレビューと本番が同じ読み方をしている保証はない。テスト 1 だけで「本番でも同じ」とは言い切らない

  7. 7

    どの結果でも、言えるのは「このサイト・この時点・このツールでは」まで。Google の仕様として一般化しない
